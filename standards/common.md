# 通用工程规则

适用：所有已接入项目。规则是行为要求，不等于自动检查已经执行。

## 判断与范围

- 将用户目标、提出的方案、已确认事实和未知项分开。发现方案不满足目标时给出证据、代价与推荐替代；不一味赞成，也不机械反对。
- 简单明确的改动直接做；只有答案会实质改变实现、权限或验收才提问。用户授权完成任务不等于授权部署、发邮件、改数据库或修改其他工程。
- 阅读目标仓库及子目录的有效 AGENTS/override、项目事实、相关 Skill。按范围加载，不把所有框架标准塞入每次任务。
- 用户当前明确要求和平台指令优先；本 Kit 是项目可配置的默认基线。地方规则与基线冲突时显式解释，不悄悄选择方便的一条。安全约束不能通过普通配置绕过。
- 保留未提交改动，最小必要 diff；不为局部任务批量迁移目录、替换框架或更新全部依赖。

## 代码与数据

- 按业务对象/能力组织文件，按明确动作命名；组件/服务只承担清晰职责，不按每个点击机械拆文件。
- 边界隔离优先于抽象数量。复用纯业务规则、契约和设计 token；不要为了共享强行统一不同产品的 DOM 或不同框架的 Store。
- 明确 API host、认证域、方法、参数、分页、错误及空值。不能从页面域名猜接口域名，也不能假设所有服务采用同一种 401 策略。
- 不把返回对象直接 spread 到保存 payload；使用已确认字段 allowlist。标识符保持精度；只有接口契约明确时才转换类型，超安全整数不得直接 Number()。
- 状态使用原始字段和生命周期上下文精确映射，未知值不能冒充成功；测试覆盖枚举组合、0/false/空数组/缺失字段的区别。
- 接入真实接口后清理替代掉的生产 mock；隔离测试 fixture 可以保留。接口缺口不能用假成功掩盖。
- 对外部输入做边界校验，不记录凭据、完整敏感响应或未经脱敏的 trace。

## 完成与证据

- 修改前定义可观察验收：给定数据、操作、期望请求和界面结果。
- 测试失败定位后修正并重跑；不删除断言、放宽规则或把必需检查设可选来制造绿灯。
- 静态检查、单元测试、浏览器操作、真实 API、生产部署是不同证据；未执行就明确未验证。
- 自测不称为独立 QA；需要独立审查时使用独立上下文并说明权限，不为了展示“团队”创建无意义 Agent。
- 交付给出变化、证据、限制和剩余风险，不要求用户替代本可执行的自动验证。
