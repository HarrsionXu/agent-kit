# 后端与数据标准

当前参考 NestJS/Prisma 工程，通用原则可复用；具体数据库、响应包装、迁移策略属于项目事实。

- NestJS Controller 薄层、Service 承担业务、DTO 承担输入校验；按业务模块组织并核对注册、权限和文档。
- 公开接口显式声明；权限与资源归属在服务端验证，不能相信前端隐藏或客户端传入 owner。
- 统一项目现有错误/响应语义，不为统一外观吞掉异常或泄露数据库内部错误。
- schema、DTO、字段长度、导入模板、响应和消费端契约一致；长 ID 不丢精度，分页/枚举/语言按实际接口确认。
- 导入校验和普通表单保存复用业务不变量；流式进度可追踪批次、部分失败与重试，不跳过审计。
- 文件保存 key/URL 方案按服务契约，不照搬某项目 OSS 域名；校验归属、类型、大小和授权。
- 数据变更先核对环境与连接目标，再设计迁移、备份/恢复和兼容窗口；生成迁移不等于获准执行迁移。
- 已执行迁移不重写；不拿 db push/重跑 bootstrap 作为通用修错方式。测试和生产迁移政策分别来自目标项目。
- 测试覆盖校验、授权、事务、幂等/并发和失败回滚。数据库或 Redis 集成测试需要明确隔离目标。
- .env、凭据、真实用户数据不进入规则仓库或测试证据；生成代码不手改。
