# 前端通用标准

适用 UI/交互任务；不指定 Vue/Angular/React，也不统一不同产品形态的根字号。

## 设计依据

先读项目设计 token、现有基础组件及用户认可的样板。项目未选定样板时不把任意历史页面当权威。

业务工作台默认信息优先、装饰克制；不新增无业务价值的毛玻璃、大面积渐变、重阴影或重复说明块。品牌/营销页面按明确目标另行判断。

保持字号层级、动作位置、错误反馈和状态语义一致。复用既有 CSS 策略；Tailwind、Element Plus、OS* 等是项目选择，不能全局强制。

若项目已安装 ui-ux-pro-max，UI 设计/实现时读取其 SKILL 并按路由使用；它不能覆盖已确认设计系统。未安装则说明不可用，继续使用项目依据，不伪称调用，也不自动安装。外部 Skill 应固定来源与版本。

## 行为

- 区分只读展示与可编辑字段；必填标记、校验和保存契约一致。
- 提交有反馈、防重复；失败保留输入并可重试；必要时处理过期响应，避免快速切换串数据。
- 保存/Start 后按约定重新取数，保留筛选、页码、排序和展开上下文；展开折叠不挪动表头。
- 长名称可获取全文；弹层可翻转/限制高度，卡片滚动不越界，固定导航不随内容消失。
- 覆盖 loading/empty/error/readonly/permission；不把错误伪装为空列表，不重复堆叠状态提示。
- 键盘焦点、标签、图标可访问名称和非颜色状态表达必须可用；动效尊重减少动画设置。
- 复杂表格可容器内横向滚动，不用一条通用移动端规则隐藏关键业务列。
- 测试完整操作路径，截图不能代替点击/刷新/失败恢复。记录视口、数据状态、控制台与网络检查范围。

## API 与共享

统一契约与错误语义，HTTP 通过框架适配层调用。各端不复制状态映射和权限算法，但不强制共享页面 DOM、整个响应式 Store 或组件实例。

国际化范围由项目确认；字段/状态文案从同一映射产生。日期格式与时区明确，不能把时间戳原样显示。
