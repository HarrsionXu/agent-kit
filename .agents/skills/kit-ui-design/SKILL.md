# 前端设计阶段

先确定当前任务是方案、原型还是已获授权的实现。读取有效项目规则、设计基线和相关组件；安装项目读取 `.agent-kit/rules/frontend.md` 与 `frontend-design.md`，维护 Kit 时读取 `standards/` 中的同名规范。不要因设计任务切换业务技术栈。

## 选择工作量

- 既有模式内的小调整：说明预期，沿用基线实施和验证，不要求新设计稿或额外确认。
- 新页面或关键交互：先输出可审阅原型；已有明确设计确认时直接继续实现，不重复确认。
- 新产品或整体布局变化：先确定核心任务与信息结构，再验证代表性页面，不一次铺开所有页面。
- 用户只要方案或审查时保持对应边界，不擅自进入实现或真实业务操作。

## 做出可审阅设计

1. 从需求、已有契约提炼用户任务、入口、主要信息与动作、完成条件及相关状态。将未知业务语义明确列出，不用演示数据替用户决定权限、流程或阈值。已有 PRD 直接引用。
2. 确认适用端、token、组件与样板的来源。没有认可样板时标记候选，先用权威组件做原型；需要新基线时参考 `templates/design-baseline.md`（安装项目在 `.agent-kit/templates/`），在项目自有文档中记录，不写进 Kit 模板。
3. 先确定信息分组、动作位置、导航/返回、编辑载体与错误恢复，再调整视觉。说明关键取舍；只在有实质差异时给备选方案。不自行添加页面级标题、问候或宣传横幅。
4. 用项目框架和组件制作隔离的浏览器原型，使用有类型的合成 fixture 并标识演示用途。演示核心路径及相关空/失败/只读状态，不调用真实审批、通知或删除。无运行条件时交付草案，明确尚未在浏览器验证。
5. 在浏览器验证核心操作、长内容、目标视口、焦点和错误恢复，修正可复现问题。按需用 `templates/ui-design.md` 记录入口、基线、状态、证据与待确认决定；小任务可在对话记录。
6. 新设计尚未确认时交付原型和具体待定项；确认后在既有授权内实现，按 `kit-ui-review` 验收。推广基线前保留确认依据；外观确认不等于业务、工程或发布验收。

## 外部参考

ui-ux-pro-max 是可选检索资料；项目基线已能解决的问题直接复用。确有具体知识缺口或用户指定时才读取并使用它，说明实际采纳的建议。工作台检索出营销结构时拒绝套用；存量新增页面不自动生成新主题。缺少外部 Skill 不阻断任务，也不自动安装。

## 输出

交付本次范围内的设计依据、可查看入口或草案、已验证的任务/状态、实际证据及未验证项。把候选、已确认、已实现、已验证分别标清；不能将自己的推断或检索结果写成用户已经认可。
